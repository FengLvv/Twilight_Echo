# 歌曲分析预加载验收

2026-10-31，Windows / RTX 5080。本记录区分真实模型、应用集成和可重复的逻辑回归，不将阶段耗时当作网络歌曲端到端等待或 P95。

## 已交付

- 主分析与人声旋律各自复用常驻 Python 进程，六轨和 SheetSage2/MERT2 预加载；可选多人声与旋律按需加载。内存压力先释放可选组件。取消采用安全点，退出有进程树回收。
- Core 单队列负责优先级、共享需求、取消、字节预留、实际使用 LRU 和播放／导出／推理租约。只读取真实播放队列的确定下一项，不扫描歌单或资料库。
- 默认 2 GiB 音频上限，原曲 PCM、六轨、子轨、临时音频与混音描述计入预算。小型结果不随音频淘汰。
- SQLite 中和弦、原始音符、最终 SVG 和波形各一份 Brotli 压缩产物。摘要不嵌入整份谱面。音源身份采用解码 PCM，忽略 FLOAT WAV 头部的生成时间；JSON 数字跨语言规范化。
- 谱面生成使用临时目录；MIDI、MusicXML 按需从原始音符导出。没有任务结果 JSON 或第二份长期 SVG。
- 原生设置页提供下一首预分析、容量、用量及清理；CLI 提供同一组能力。保留整曲模型、原生完整音频混音、歌词和桌面歌词路径。
- 开发期旧项目表直接替换，没有旧格式迁移分支。原始歌曲、账号、用户导出不属于缓存回收范围。

## 验证结果

1. 174 项 Node 回归通过：缓存容量与并发预留、LRU、租约、失败删除、SQLite 重启、小结果独立有效性、任务合并／提升、顺序／随机／循环、暂停队列和歌曲切换、歌词投影与谱面。
2. Python 阶段／身份测试 8 项、曲谱与原词映射 7 项、常驻协议取消与进程复用 1 项通过。三套 TypeScript 检查通过。
3. 两项真实平台测试通过：HTTP 下载与离线复用、两种人声子轨复用六轨、WAV/FLAC 及三种和弦格式导出、取消加入、环境并发初始化、退出和重启运行时。
4. 真实模型驱动连续分析两段音频，六轨和和弦模型各只加载一次。28 秒人声片段生成 12 行谱面；删除全部音频后可继续读谱，仅重排可完成；恢复六轨保持原和弦、音符和谱面不变。MIDI / MusicXML 导出与取消后复用运行时通过。
5. 打包应用在独立配置目录中验证设置双向变更及宽／窄窗口，无横向溢出或页面异常。真实播放队列只有《My Friend》和《青花瓷》，点击当前歌曲分析后，仅后台准备实际下一首。清理跳过下一首租约；关闭预取后音频降至 0 字节，两首和弦仍可读取。
6. 修正真实接入中发现的普通队列预取被误判为推荐流的问题，新增“推荐服务已接入但未启用”的回归。修正 Windows 原生依赖在控制线程启动后的导入阻塞及排版器继承 RPC 输入管道导致的超时。
7. Impeccable 机械检查无命中；使用原有设置组件。Windows 品牌、打包依赖闭包和渲染资源预算检查通过。

## 实测耗时

音源已经在本地，主模型预热完成，没有缩短和弦上下文或替换模型。

| 样本 | 时长 | 解码 | 六轨阶段 | 和弦阶段 |
|---|---:|---:|---:|---:|
| My Friend | 231.46 秒 | 0.54 秒 | 4.23 秒 | 7.59 秒 |
| 青花瓷 | 268.88 秒 | 0.20 秒 | 5.02 秒 | 8.98 秒 |

六轨阶段包括推理、音频写入、波形和指纹提交，不包括解码及随后 Core 轮询／音频切换。两首顺序完成约 29.06 秒；重复当前分析命令约 229 毫秒，包含 CLI 进程与 IPC。它们是单次样本，未验收三分钟音频 P95 ≤ 5 秒的目标。

常驻驱动一次冷预热约 34.33 秒，包括导入与内核预热，后台执行。28 秒片段的首次旋律识别约 26.96 秒，排谱约 5.08 秒；只重排约 4.64 秒，完整旋律结果复用约 8 毫秒。该片段含 12 行歌词，不能用于外推整曲旋律耗时。

两首完整歌曲的和弦及波形压缩后共 21,779 字节；28 秒测试的和弦、波形、原始音符和谱面共 18,954 字节。尚未为任意整曲谱面设定固定大小承诺。
