# 《新世界》简谱失败修复

2026-11-01；Windows / RTX 5080；复现自当前优化版的网易云歌曲 `1436961077`。

## 原因与修复

- 45 秒对齐上下文混有中文和 `Say it's a new world`，此前只启用中文发音表。实际复现为 `Unknown phonemes ['say']`。现在 TiFA 接收当前上下文的语言集合，并保留每个词的语言；GAME 按词选择元音和英语音节边界。日本歌中的汉字沿用日语上下文，纯英文歌词仍用英语转换器。
- 原歌词末尾的“人声编辑”“鼓录音”“和声&和声设计”等署名被错误送去对齐，随后在 `55TEC` 处再次失败。Core 与独立人声运行时共用 `lyric_credits.json` 的明确角色表，只排除带冒号的署名头，普通歌词保留。独立运行时同样过滤已有任务冻结的歌词，重试不再反复使用错误的署名输入。原始歌词显示及行 ID 保持不变。
- 音符完成后发现 jianpu-ly 的 MusicXML 转换只支持简单／附点弱起长度，3.5 拍弱起会丢失起拍信息并触发跨小节检查。只在中性简谱的渲染输入中，把首尾截短小节表示为精确长度的局部拍号，隐藏拍号显示。全部音符时值、跨小节延音和索引保留；不补首尾休止、不关闭小节检查。原始 MIDI / MusicXML 导出仍使用原来的弱起和拍号。
- 发音转换、发音编码和时间对齐错误会保留具体原因，避免只剩“歌词无法对齐”的片段截断消息。

旋律算法键和排版键更新为 `vocal2midi-tifa-game-medium-rhythm-v2` / `lyric-phrase-v2`；只有旋律算法变化需要重新识别，单独排版版本变化只重排，六轨及和弦不重跑。

## 验证

- 使用实际 351.278 秒音频及原来冻结的 80 行输入，过滤 5 行署名，生成 548 个音符；75 行演唱歌词全部有音符。
- 对齐成功后生成 75 行原生 SVG；逐个检查 `data-note` 与所属原文行的索引关系。
- 空闲 CPU 状态后复用全部结果，音符逐值一致，未重新进行对齐／音高推理。
- 中文／英语、日语／英语真实发音表编码测试、英语多音节与中文词混合的元音边界、署名与冻结任务重试、31 种八分之一拍网格的弱起长度通过。
- Core / Agent / 桌面歌词 / 缓存 / 播放等 190 项回归通过；新增 3 项缓存版本与独立产物检查通过；三套类型检查通过。

本机证据在 `.local/vocal-mixed-bug/`，其中 `g2p.log` 记录原始失败，`fixed-full/notes.json` 为整曲识别结果，`final-score/verification.json` 为完整排谱与缓存复用检查。歌曲音频和歌词不提交到仓库。

复现入口：`scripts/verify-study-multilingual.mjs`，需要包含 `original.wav` / `vocals.wav` 的目录、冻结的时间歌词 JSON、模型环境及输出目录。`--notes` 可单独重排已有音符，`--runtime` 可检查打包资源中的运行时。

修复包：`dist/study-lyrics-fix/win-unpacked/TwilightEcho.exe`。
