# 歌曲分析优化验证

2026-11-01；Windows / RTX 5080；完整离线模型。以下是单机单次测量，不是 P95。

## 已实施

1. Core 保持唯一调度器。两个人声 / 主分析 Python 运行时共用模型权重预算，切换大型模型前停放另一族；可选 Torch 与 ONNX / DirectML 模型空闲 30 秒转 CPU，六轨保留在 CUDA。模型位置变化失败会显式标记并在使用前修复。DirectML 权重按文件估计，不能当作整卡显存硬上限。
2. 原生 LilyPond 每批最多 16 个独立歌词文件，一批一个进程，完整保留原来的排谱引擎、音符时间映射和字体。取消会停止并等待当前拥有的排谱进程，所有中间文件仍位于临时目录。
3. 原有 45 秒歌词上下文保持不变。每个上下文按文本、音频范围与实际语言建立内容指纹，复用独立的节拍网格；改动只重算指纹变化的上下文。删除 / 插入歌词导致上下文重新组合时，受影响的新组合会正常重算。
4. 只保存一份原始音符。复用元数据保存各上下文的音符索引，重新编号时重映射歌词 ID / 词 ID；谱面按节奏和原词指纹复用，并重写全部 `data-note` 索引，包括跨小节延音。调式和显示音高不触发中性简谱图形重排。旧结果保留作复用输入，新的歌词结果完成前不作为当前可用曲谱显示或导出。

## 真实歌曲结果

《青花瓷》全曲 268.879 秒，68 行歌词，5 个上下文。

| 检查 | 结果 |
|---|---:|
| 同一份原始音符，原来逐行启动排谱 | 27.86 秒 |
| 同一份原始音符，批量启动排谱 | 11.25 秒 |
| SVG 几何对照 | 68 / 68 行逐字节一致 |
| 一行文字修改后重算 | 1 个上下文，另 4 个逐值复用 |
| 文字修改后的识别 / 排版 | 7.98 秒 / 0.43 秒，含从空闲状态恢复 |
| 全部歌词 ID 改号 | 0 次对齐 / 音高推理；全部 5 个上下文复用 |
| 改号处理 / 排版 | 333 ms / 11 ms |
| 完整命中缓存 | 4 ms；未恢复 DirectML 到 GPU |
| 全部模型空闲 CPU 后强制重新识别 | 原始音符逐值一致 |

首次整曲旋律约 63 秒，包含独立环境导入、CPU 模型初始化、DirectML 提供器建立、节拍与整曲逐词音高识别；后续局部修改的 8 秒不能直接作为冷启动整曲耗时。六轨本次约 4.9 秒，算法 / 模型 / 整曲上下文没有缩减。

Duet 使用真实完整权重检查预算淘汰：和弦被停放到 CPU，六轨保留 CUDA；再次恢复 Duet 约 356 ms，固定输入 / 噪声的两步去噪结果逐值一致。此检查验证设备搬运与执行，未把两步样例冒充默认 100 步全曲分离质量测试。

## BF16 权重评测：保持 FP32 权重

两个候选在独立新进程中加载，使用冻结的同一份代码、相同 `paper` 解码、整曲上下文和 BF16 自动混合计算。唯一变量为持久权重 FP32 / BF16。样本包含 GuitarSet 的波萨诺瓦、放克、爵士、Singer-songwriter、摇滚各一段，《My Friend》《青花瓷》全曲，以及 FutureMIREX 两首爵士演示曲。

- 参数体积：2,707,549,796 → 1,353,774,898 字节，减半。
- 此批样本推理约快 10%–13%；没有计入模型冷加载。
- 9 个样本有 5 个标签 / 时间边界完全一致；爵士吉他样本的时间加权结果一致率约 83.25%，`puppet_master` 约 98.75%。两个流行整曲也有约 10 ms 边界差异。
- 这些是与当前结果的一致率，不是真值准确率；不能把差异直接解释为准确率下降。它们足以否决“不改变结果”的启用门槛。因此维持当前 FP32 权重 + BF16 自动混合计算，没有新增用户设置。
