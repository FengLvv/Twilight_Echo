# 播放页与旋律识别修复（2026-11-01）

《芬兰距离》的旋律任务在模型推理之前失败。结尾制作公司署名行的时间是 349.203–350 秒，实际解码时长为 349.541723 秒。旧流程在清理署名之前就进行了音频时长校验。

现按“结构校验 → 网易云歌词既定清理（词表、分类模型、人声首尾）→ 剩余演唱行时长校验”执行。AMLL 结构化主唱歌词继续跳过启发式清理。保留行越界会提示具体行号和时间，没有通过放宽容差吞掉错误。

使用原曲和当次任务的完整歌词独立重跑成功：266 个音符、45 行谱面；v4 模型提出的 7 行署名候选均位于人声结束之后，最终移除。音高和排谱均为模型输出，不构成独立人工听辨校准。

格式菜单改为按钮居中并采用项目 popover 材质的配套文字颜色。在 1440 / 900 两种宽度测试亮、暗菜单，未选格式对比度至少 4.5:1。

流媒体搜索默认选择网易云，直接保留 `/cloudsearch?type=1` 返回的顺序和不同版本。用户另选“全部来源”时仍保留原有多来源合并排序；未修改歌单手动排序。

多轨切换现在读取原生服务的新鲜播放位置，准备完成后保留原生引擎已经推进的位置，修正旧请求位置覆盖时钟造成的回跳。相关原生服务缓存和时钟回归通过；本次没有打断常用播放器进行硬件试听，不能据此宣称硬件层零中断。

分类模型升级为 `minilm-v4-real1092-precision`，校验 ONNX、tokenizer、manifest 三项 SHA-256，阈值 0.9928489731384277。安装在独立版本目录，当前仍运行的旧包可以继续使用其旧目录。新模型的冻结参考误删统计及局限见用户提供的选型报告，没有宣称零误删。

验证：462 项 Node 回归、39 项 Python 测试、Core / Node / Web 类型检查、生产构建、字体与 renderer 预算检查通过。新包独立 profile 启动进入 ready 并请求正常退出。归档 264 个编译文件与当前构建一致；5 个 Python / JSON 资源逐项校验一致。
